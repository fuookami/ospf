停机日历与滚动重排：保留事实，再优化未来 ​

完成第一次活动排程后，先增加停机与分时容量，再处理实际执行记录和基准排程。基准排程是用于比较调整幅度的原计划；已经执行的活动则是必须保留的事实，不能仅靠高额罚费鼓励模型保留。

1. 用一个活动识别“只检查起点”的错误 ​

活动持续 2 h，全程占设备容量 2；允许起点为 0、2、4 h。设备正常容量为 2，在 [1,2) 停机，在 [3,4) 容量降为 1。

开始占用区间是否可行原因
0 h[0,2)否跨越停机段
2 h[2,4)否后半段容量不足
4 h[4,6)是全程容量充分

沿用第一课的 at、q 和资源 ID，把停机与容量覆盖显式传入 ActivityResource。注意左闭右开区间：4 h 开始不占用 [3,4)。

2. 把容量日历接到资源，不是活动标签 ​

构造与表格一致的活动和日历 ​

完整函数定义 at 为统一时间原点后的小时、q 为无量纲容量；资源、占用量和允许起点一起构造，因此可直接验证 0、2、4 h 三个选择。

    listOf(at(0), at(2), at(4)), listOf(ActivityResourceUse(machine, q(2.0))), q(0.0))))

3. 在滚动时刻划清三类数据 ​

以现在为 0 h：一个运行中的活动在 -1 h 开始、2 h 完成，在未来窗口占设备 [0,2)；一个已完成活动在 -3 至 -2 h 执行；其余活动仍待决策。

  • 实际执行记录：保留原始开始/完成与状态；只把剩余资源占用放入未来窗口，不能重新排成 0 h 开始的完整任务。
  • 冻结选择：已经承诺的开始/模式属于硬限制；新停机与其冲突时，应报告冲突/不可行，而不是为了低费用偷偷移动。
  • 可调整基准排程：允许改动，但按实际配置计调整代价；基准排程不是强制实际执行记录，也不会自动生成新允许起点。

把实际执行记录传入 executions，把承诺的选择与可调整基准传入 baselines；依赖引用必须保留相同任务 ID。不要把已完成活动重新加入待排活动列表，也不要把运行中活动的完整资源占用再次计入未来窗口。

保持入口，区分允许起点与搜索上限 ​

将上述问题传回第一课的活动服务即可，无需切换列生成入口。starts 定义全部允许起点，不是搜索次数上限。求解时间和节点数上限在实际后端适配器中配置；达到时限时，应同时记录是否已找到可行解。

    ActivitySchedulingApplicationService(solver, schedulingSolverValueAdapter).solve(makeProblem())

4. 做两次受控变更 ​

最小扩展：晚起点加收费用 ​

本例另加“4 h 及以后开始收费 2”的偏好。Kotlin 用 additionalCost 注入 ActivitySchedulingProblem；Rust 的闭包实现 ActivityCostPolicy，在创建上下文对象时传入。容量仍是硬约束，附加费用只影响合法选择的排序。

  1. 在上表中删掉 4 h 起点。若活动必须执行且不能取消，当前允许起点中没有可行选择；框架不会自动增加 6 h 起点，也不会自动把活动改成可中断执行。
  2. 恢复起点，先添加一个冻结选择，再让它与停机重叠。确认正常不可行与输入技术错误分开处理，并明确由谁授权解除冻结。

新增起点、换资源、允许取消是三种不同业务决定，要分别配置和验收。取消活动还需检查前后依赖与物料事件，不能仅从画面删除条形。

5. 重排交付验收 ​

保留已完成活动的执行记录、运行中活动的原始时间和剩余占用；冻结选择不变；可调整活动只在允许候选中选择；全程资源、依赖和库存符合要求；调整费用可重算。达到时限后返回的可行解仍需标明时限状态。

滚动过程中使用输入版本或请求号避免旧结果覆盖新状态。更多建模约定见滚动优化，应用边界见接入指南。

源码回归命令统一放在仓库验证参考；先完成业务输入、调用与结果复核，再按需验证。

完整应用源码 ​

片段来自同一个源码文件；保留导入声明和辅助函数后，从应用调用 runBusiness / run_business。构造函数也可独立用于输入校验。后端依赖沿用第一课；这些入口不创建隐式求解后端。

kt
@file:OptIn(kotlin.time.ExperimentalTime::class)
package docs.examples.gantt.business

import kotlin.time.Instant
import kotlin.time.Duration.Companion.hours
import fuookami.ospf.kotlin.math.algebra.number.Flt64
import fuookami.ospf.kotlin.quantities.quantity.Quantity
import fuookami.ospf.kotlin.quantities.unit.NoneUnit
import fuookami.ospf.kotlin.framework.solver.ColumnGenerationSolver
import fuookami.ospf.kotlin.framework.gantt_scheduling.infrastructure.TimeRange
import fuookami.ospf.kotlin.framework.gantt_scheduling.domain.task.model.*
import fuookami.ospf.kotlin.framework.gantt_scheduling.domain.activity.model.*
import fuookami.ospf.kotlin.framework.gantt_scheduling.application.service.*

private data class Task(val value: String) : TaskId
private data class Resource(val value: String) : ExecutorId

fun makeProblem(): ActivitySchedulingProblem<Flt64> {
    val origin = Instant.parse("2026-10-22T00:00:00Z")
    fun at(hour: Int) = origin + hour.hours
    fun q(value: Double) = Quantity(Flt64(value), NoneUnit)
    val machine = Resource("machine")
    // #region input
    val resource = ActivityResource(machine, q(2.0),
        unavailableTimes = listOf(TimeRange(at(1), at(2))),
        capacities = listOf(ActivityCapacity(TimeRange(at(3), at(4)), q(1.0))))
    val task = Activity(Task("a"), listOf(ActivityMode("normal", 2.hours,
        listOf(at(0), at(2), at(4)), listOf(ActivityResourceUse(machine, q(2.0))), q(0.0))))
    // #endregion input
    // #region rule
    val lateStartFee: (ActivityPlacement<Flt64>) -> fuookami.ospf.kotlin.utils.functional.Ret<Quantity<Flt64>> = { placement ->
        fuookami.ospf.kotlin.utils.functional.Ok(q(if (placement.key.start >= at(4)) 2.0 else 0.0))
    }
    return ActivitySchedulingProblem(horizon = TimeRange(at(0), at(6)), activities = listOf(task),
        resources = listOf(resource), costUnit = NoneUnit, additionalCost = lateStartFee)
    // #endregion rule
}

// #region entry
suspend fun runBusiness(solver: ColumnGenerationSolver) =
    ActivitySchedulingApplicationService(solver, schedulingSolverValueAdapter).solve(makeProblem())
// #endregion entry

rs
use time::{Duration, OffsetDateTime};
use ospf_rust_framework::solver::{ColumnGenerationSolver, FrameworkSolveOptions};
use ospf_rust_framework_gantt_scheduling::application::service::ActivitySchedulingApplicationService;
use ospf_rust_framework_gantt_scheduling::domain::activity::*;
use ospf_rust_framework_gantt_scheduling::domain::common::{task_id, executor_id};
use ospf_rust_framework_gantt_scheduling::domain::task::F64SolverValueAdapter;
use ospf_rust_framework_gantt_scheduling::infrastructure::TimeRange;
use ospf_rust_quantities::{Quantity, unit::{CTUnit, NoneUnit}};

pub fn make_problem() -> ActivitySchedulingProblem<f64> {
    let at = |h| OffsetDateTime::UNIX_EPOCH + Duration::hours(h);
    let q = |value| Quantity::new(value, NoneUnit::INSTANT.clone());
    // #region input
    let resource = ActivityResource { id: executor_id("machine"), capacity: q(2.0),
        unavailable_times: vec![TimeRange::new(at(1), at(2))],
        capacities: vec![ActivityCapacity { time: TimeRange::new(at(3), at(4)), capacity: q(1.0) }] };
    let mode = ActivityMode { id: "normal".into(), duration: Duration::hours(2), starts: vec![at(0), at(2), at(4)],
        resources: vec![ActivityResourceUse { resource: executor_id("machine"), quantity: q(2.0), from: Duration::ZERO, until: None }],
        cost: q(0.0), material_flows: vec![] };
    let task = Activity { id: task_id("a"), modes: vec![mode], cancellation_cost: None };
    // #endregion input
    ActivitySchedulingProblem { horizon: TimeRange::new(at(0), at(6)), activities: vec![task], resources: vec![resource],
        dependencies: vec![], baselines: vec![], executions: vec![], rows: vec![], cost_unit: NoneUnit::INSTANT.clone(),
        materials: vec![], material_events: vec![] }
}

pub fn run_business<S: ColumnGenerationSolver>(solver: S) -> Result<(), String> {
    // #region rule
    let late_start_fee = |p: &ActivityPlacement<f64>| -> ospf_rust_framework_gantt_scheduling::GanttResult<_> {
        let late = p.key.start >= OffsetDateTime::UNIX_EPOCH + Duration::hours(4);
        Ok(Quantity::new(if late { 2.0 } else { 0.0 }, NoneUnit::INSTANT.clone()))
    };
    let context = ActivitySchedulingContext::new(make_problem(), &F64SolverValueAdapter,
        Some(&late_start_fee), Default::default()).map_err(|e| format!("{e:?}"))?;
    // #endregion rule
    // #region entry
    let report = ActivitySchedulingApplicationService::new(solver)
        .solve(|| Ok(context), FrameworkSolveOptions::default()).map_err(|e| format!("{e:?}"))?;
    println!("{report:?}");
    // #endregion entry
    Ok(())
}
