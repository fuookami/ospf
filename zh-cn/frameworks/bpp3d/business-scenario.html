多箱型与目标配置：先说明“装得好”是什么意思 ​

在第一次三维装箱接通最终选择和装载分析后，再加入第二种箱型。这个新练习只用正方体，避免让复杂朝向掩盖目标配置问题。

1. 一个能区分目标的场景 ​

货物为 2 × 2 × 2 m 正方体，共 10 件，净体积 80 m³。承重充分，不加额外间距、支撑或平衡规则：

箱型内尺寸体积可用箱数单箱费用
S4 × 4 × 4 m64 m³24
L4 × 4 × 6 m96 m³110

一箱 S 最多放 8 件；一箱 L 可按 2×2×3 网格放 12 件，因此可以选择一箱 L，或两箱 S。体积消耗分别为 96、128 m³，费用分别为 10、8。最少箱数与最少体积消耗偏好 L，最小费用偏好两个 S。

下面把这组数据落到请求和目标配置中。手算用于比对实际启用箱体，最终是否可交付还取决于执行器产生的坐标与完整需求覆盖。

2. 多箱型有三处要同时接通 ​

从手算数据构造请求 ​

Kotlin 复用第一课的 makeItem(edge = 2.0)，创建 S、S、L 三个箱体实例，并按网格顺序放入 1 件、2 件直至达到容量上限，生成带实际坐标的候选层；完整函数见页末。Rust 每件货物使用单独记录，从 CSV 加载并转换得到米制几何、箱体与初始候选；amount 记录与最终实际放置件数都需保留。

kt
val item = makeItem(edge = 2.0)
fun bin(id: String, depth: Double) = BinType(width = FltX(4.0) * Meter, height = FltX(4.0) * Meter,
    depth = FltX(depth) * Meter, capacity = FltX(100.0) * Kilogram,
    longitudinalBalance = null, lateralBalance = null, typeCode = binTypeIdOf(id))
val small = bin("S", 4.0)
val large = bin("L", 6.0)
val physicalBins = if (smallOnly) listOf(small, small) else listOf(small, small, large)

两种输入路径

Kotlin 候选包含实际放置，Rust CSV 的 layers 记录只给出初始候选层元数据，实际几何还取决于执行器生成与重建；不要将 layers 记录数当作可交付装箱。Rust 当前米制接口还共享重量/长度单位类型，生产接入需单独校验重量归一化。

  1. 生成请求携带全部箱型：Kotlin Bpp3dLayerGenerationRequest.bins；Rust LayerGenerationRequest.bins。
  2. 每列保留来源箱型，不能把同坐标、不同箱型的层合并。
  3. 最终模型有真实可用箱体：Kotlin finalBins；Rust 对应最终整数求解执行器的箱体输入。只增加箱型目录不等于可用箱体数量不限，数组下标也不应成为跨请求 ID。

然后对同一货物 ID 设置精确 10 件需求，按第一课的请求构造函数同步维护需求表示、初始候选列和最终箱体。不要把一箱 S 的 8 件容量写成订单需求。

3. 显式配置目标，而不是猜默认值 ​

意义Kotlin 配置字段Rust 配置字段
体积消耗权重finalBinVolumeWeightfinal_bin_volume_weight
箱数系数finalBinAmountCoefficientfinal_bin_amount_coefficient
箱型费用权重finalBinTypeCostWeightfinal_bin_type_cost_weight
箱型费用表finalBinTypeCostsfinal_bin_type_costs

配置定义见 Kotlin 标准执行器和 Rust 执行器配置。当前默认体积权重为 1、箱数系数为 1e-6、费用权重为 0；只填费用表不会让费用自动主导结果。

先分别做纯目标实验：只保留体积权重，或只保留费用权重。再把箱数系数设零，研究归一化后的 score = consumed_volume + λ × cost：L 得分 96 + 10λ，两个 S 得分 128 + 8λ；λ=16 打平，超过 16 后费用偏好反转。这里体积数值统一按 m³ 取值，权重需要有明确换算规则。

加权求和不自动保证“先最小体积、后最小费用”。若业务要求体积始终优先，可评估分阶段求解：先求最小体积，固定其最优值后再求最小费用。若使用权重，则需依据目标取值范围证明其优先级；默认 1e-6 不对所有数据规模提供这一保证。

生成规则与结果校验器的区别

PackingGeometryContract 的自定义检查在装箱分析时执行；它只拒绝交付，不会自动把规则加入受限主问题或定价。因此完整源码在求解前也过滤了箱体和初始候选。新增混装、跨层或总预算规则时，应在对应生成/建模路径约束，最后再用校验器复核。

  • 恰好装入 10 件，不允许同一件货物在多个选中层中重复计数。
  • 所有实际放置在箱内，不重叠，朝向、承重和启用的支撑规则合法。
  • 按实际使用箱体重算箱数、96/128 m³ 消耗和费用；余量分别为 16/48 m³。
  • 受限主问题与最终整数求解阶段均使用正确扩展及后端；finalSolved 或对应诊断、实际装箱结果和实际放置共同检查。

目标系数与实际求解范围分开记录；系数配置正确不代表候选完备，也不代表新场景已被证明全局最优。

若最小箱体单件也装不下，先查方向和候选；若候选有了但最终无方案，再查可用箱体、需求和跨层几何。按接入指南保存原始诊断，不要仅通过增加迭代次数排错。

源码回归命令统一放在仓库验证参考；先完成业务输入、调用与结果复核，再按需验证。

完整应用源码 ​

片段来自同一个源码文件；保留导入声明和辅助函数后，从应用调用 runBusiness / run_business。构造函数也可独立用于输入校验。后端依赖沿用第一课；这些入口不创建隐式求解后端。

package docs.examples.bpp3d.business

import docs.examples.bpp3d.makeItem
import fuookami.ospf.kotlin.math.algebra.number.*
import fuookami.ospf.kotlin.quantities.quantity.times
import fuookami.ospf.kotlin.quantities.unit.*
import fuookami.ospf.kotlin.framework.solver.ColumnGenerationSolver
import fuookami.ospf.kotlin.framework.bpp3d.infrastructure.*
import fuookami.ospf.kotlin.framework.bpp3d.domain.item.model.*
import fuookami.ospf.kotlin.framework.bpp3d.domain.layer_generation.*
import fuookami.ospf.kotlin.framework.bpp3d.application.service.*

private object Grid

fun makeRequest(costObjective: Boolean = false, smallOnly: Boolean = false): ColumnGenerationApplicationRequest {
    // #region input
    val item = makeItem(edge = 2.0)
    fun bin(id: String, depth: Double) = BinType(width = FltX(4.0) * Meter, height = FltX(4.0) * Meter,
        depth = FltX(depth) * Meter, capacity = FltX(100.0) * Kilogram,
        longitudinalBalance = null, lateralBalance = null, typeCode = binTypeIdOf(id))
    val small = bin("S", 4.0)
    val large = bin("L", 6.0)
    val physicalBins = if (smallOnly) listOf(small, small) else listOf(small, small, large)
    // #endregion input
    // Enumerate actual prefix placements, not selected bins or solver answers.
    val layers = physicalBins.distinct().flatMap { type ->
        val slots = (0 until if (type.typeCode == small.typeCode) 8 else 10).map { n ->
            itemPlacement3Of(item, QuantityPoint3(FltX((n % 2) * 2.0) * Meter,
                FltX(((n / 2) % 2) * 2.0) * Meter, FltX((n / 4) * 2.0) * Meter))
        }
        (1..slots.size).map { n -> BinLayer(iteration = Int64.zero, from = Grid::class,
            bin = type, shape = type.asContainer3Shape(), units = slots.take(n)) }
    }
    // #region rule
    val generator = object : Bpp3dLayerGenerator<FltX> {
        override suspend fun generate(request: Bpp3dLayerGenerationRequest<FltX>) =
            layers.filter { !smallOnly || it.bin?.typeCode == small.typeCode }
                .map { Bpp3dLayerGenerationResult<FltX>(layer = it, source = "approved-grid") }
    }
    val request = ColumnGenerationApplicationRequest(itemDemands = listOf(item to UInt64(10)),
        initialColumns = layers, generators = listOf(generator),
        finalBins = physicalBins.map { layerBinOf(shape = it, units = emptyList()) })
    // #endregion rule
    // #region objective
    return if (!costObjective) request else request.copy(executorConfig = ColumnGenerationStandardExecutorConfig(
        finalBinVolumeWeight = FltX.zero, finalBinAmountCoefficient = FltX.zero, finalBinTypeCostWeight = FltX.one,
        finalBinTypeCosts = mapOf(small.typeCode to FltX(4.0), large.typeCode to FltX(10.0))))
    // #endregion objective
}

// #region entry
suspend fun runBusiness(solver: ColumnGenerationSolver) {
    val request = makeRequest(costObjective = true).copy(cgConfig = ColumnGenerationConfig(iterationLimit = 12, maxColumnsPerIteration = 24))
    val response = ColumnGenerationApplicationService(solver).solve(request, packingAnalyzer = ColumnGenerationPackingAnalyzer())
    println(response)
}
// #endregion entry

use ospf_rust_framework::solver::meta_model_backend::MetaModelSolverBackend;
use ospf_rust_framework_bpp3d::application::{CsvDatasetLoader, csv::CsvMaterializedApplicationRequest, service::*};
use ospf_rust_framework_bpp3d::domain::packing::{PackedBin, service::{PackingGeometryContract, PackingGeometryGuard}};
use ospf_rust_quantities::unit::Meter;

pub fn make_request(small_only: bool) -> Result<CsvMaterializedApplicationRequest, String> {
    // The CSV adapter fixes geometry to metres; each record below is one physical carton.
    // #region input
    let mut csv = String::from("# table:items\nitem_id,name,shape_type,width,height,depth,weight,amount\n");
    for i in 0..10 { csv.push_str(&format!("i{i},carton,cuboid,2,2,2,1,1\n")); }
    csv.push_str("# table:bins\nbin_id,type_code,width,height,depth,capacity\ns1,S,4,4,4,100\ns2,S,4,4,4,100\nl1,L,4,4,6,100\n");
    csv.push_str("# table:layers\nlayer_id,bin_id,depth\ns1-layer,s1,4\ns2-layer,s2,4\nl-layer,l1,6\n");
    let mut request = CsvDatasetLoader::load_str(&csv).map_err(|e| format!("{e:?}"))?.materialize().map_err(|e| format!("{e:?}"))?;
    // #endregion input
    // Restrict both available bins and seed layers before optimization.
    if small_only {
        request.bins.retain(|b| b.type_code != "L");
        request.initial_layers.retain(|l| l.bin.as_ref().is_some_and(|b| b.type_code != "L"));
    }
    Ok(request)
}

// A delivery guard complements input restrictions; it is not a pricing constraint.
// #region rule
#[derive(Debug, Clone)]
struct SmallOnly;
impl PackingGeometryContract<f64, Meter> for SmallOnly {
    fn validate(&self, bin: &PackedBin<f64, Meter>) -> Result<(), Vec<String>> {
        PackingGeometryGuard::new().validate(bin)?;
        if bin.bin_type.type_code == "L" { Err(vec!["Only approved S bins may be delivered".into()]) } else { Ok(()) }
    }
}
// #endregion rule

pub fn run_business<R: MetaModelSolverBackend, F: MetaModelSolverBackend>(rmp_backend: R, final_backend: F) -> Result<(), String> {
    // #region objective
    let final_config = MetaModelFinalExecutorConfig { final_bin_volume_weight: 0.0,
        final_bin_amount_coefficient: 0.0, final_bin_type_cost_weight: 1.0,
        final_bin_type_costs: [("S".into(), 4.0), ("L".into(), 10.0)].into_iter().collect(), ..Default::default() };
    // #endregion objective
    // #region entry
    let config = ColumnGenerationConfig::new().with_max_iterations(12)
        .with_max_column_amount(256).with_max_candidates_per_iteration(24);
    // #endregion entry
    // #region injection
    let service = ColumnGenerationApplicationService::with_geometry_guard(config, SmallOnly);
    let request = make_request(true)?;
    let rmp = SolverBackedMetaModelRmpExecutor::new(MetaModelRmpExecutorConfig::default(), rmp_backend);
    let final_executor = SolverBackedMetaModelFinalExecutor::new(final_config, final_backend);
    let result = service.run_csv_materialized_with_bins(request, &rmp, &final_executor).map_err(|e| format!("{e:?}"))?;
    // #endregion injection
    println!("final={}, objective={:?}, diagnostics={:?}", result.final_execution.final_solved, result.final_execution.objective, result.result.info);
    Ok(())
}
