# Task 上下文领域模型

[English](../../../examples/framework-example4/domain-task/domain-model)

## 1. 概述

task 上下文负责航班任务术语和恢复输入，供规则校验、bunch 生成和 bunch 编译使用。
当前 Kotlin `FlightTaskContext` 是数据上下文，不注册优化变量族。

### 1. 依赖上下文

无。下游上下文消费其中的任务值。

## 2. 概念/实体

### 1. 航班任务

**$id_t$**：稳定任务标识；**$dep_t,arr_t$**：出发/到达机场；**$time_t$**：计划/实际时间范围；
**$aircraft_t$**：分配或可用飞机；**$status_t$**：恢复权限及硬限制标记。

### 2. 航段与恢复分配

**$leg_t$**：航段计划和航线；**$recovery_t$**：可选飞机、时间或航线变更；**$duration_t$**：任务时长。

### 3. 航班任务 bunch

分配给一架飞机的有序任务序列。**$B_b$** 为任务序列，**$aircraft_b$** 为执行器，**$cost_b$** 为计算成本。

## 3. 变量

### 1. 决策变量

无。任务和恢复值是生成列的输入。

### 2. 辅助变量

无。

## 4. 谓词

**isFlight(t)**：`t` 是航班类型任务；**recoveryNeeded(t)**：任务属于恢复集合；
**aircraftChangeEnabled(t)**、**delayEnabled(t)** 和 **routeChangeEnabled(t)**：允许的恢复操作分类。

## 5. 集合

**$T$**：所有航班任务；**$T^{F}$**：航班类型任务；**$T^{R}$**：需要恢复的任务；
**$A$**：飞机；**$B$**：候选任务 bunch。

## 6. 中间值

对于 bunch 中相邻任务，转场时间由前一任务结束与后一任务开始计算：

$$
connectionTime(t,t')=start_{t'}-end_t。
$$

## 7. 断言

每个航班任务都必须有非空标识、有效机场和一致时间范围。有序 bunch 的连续航段满足机场连续性：

$$
\forall(t,t')\in B_b:\quad arr_t=dep_{t'}。
$$

## 8. 约束

本上下文本身不贡献求解器约束；状态和时间值由规则与 bunch generation 可行性服务消费。

## 9. 目标函数

无。成本由生成 bunch 计算并由编译上下文消费。

## 10. 算法引用

没有独立算法文档。

## 11. 通用语言

| 术语 | 符号 | 定义 |
| --- | --- | --- |
| 航班任务 | `t` | 可调度的航班/恢复单元 |
| 航段 | `leg_t` | 带机场和时间的任务计划 |
| 恢复分配 | `recovery_t` | 施加到任务的可选变更 |
| bunch | `b` | 分配给一架飞机的有序任务序列 |

## 12. 设计决策

| 决策 | 备选 | 原因 |
| --- | --- | --- |
| 将任务数据与编译分开 | 在全局注册任务变量 | 支持多种生成/编译策略 |
