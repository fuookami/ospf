# 一维分切（CSP1D）：适用问题与学习路线

原料具有可用幅宽，订单需要不同宽度的产品。选择切割方案及其使用次数，让产出满足需求，并按配置处理原料、设备、超欠产与余料。

## 最少需要理解的对象

| 业务概念 | API | 角色 | 核心字段 |
| --- | --- | --- | --- |
| 产品与需求 | `Product` / `ProductDemand` | 输入 | 宽度、可选长度、数量和计量模式 |
| 原料与设备 | `Material` / `Machine` | 输入 | 幅宽、批次、设备及可选资源限制 |
| 切割方案 | `CuttingPlan` | 中间概念 | 每次执行对各产品的产出数量 |
| 问题 | `Csp1dProblem` | 输入 | 领域数据与求解配置 |
| 求解入口 | `Csp1dMilp` / `Csp1dColumnGeneration` | 调用 / 校验入口 | 方案使用、产出、需求满足与结果指标 |
| 生产结果 | `Csp1dSolution` | 输出 | 方案使用次数、单次产出、欠产、余宽、KPI |

**变量是方案使用次数，不是产品产量。** 产品产量由各方案产出乘使用次数汇总。卷数、片数、长度和重量需求不能互换。

::: tip 空值不等于零余料
`restWidth` / `rest_width()` 为空表示当前数据/算术策略无法计算，不是余宽为 0。重量与长度需求需补齐相应产品数据；产品没有重量时，不将未知重量写成 0 kg。
:::

## 从哪个入口调用？

::: info Kotlin 与 Rust 的入口差异
两种语言都提供普通 MILP 和列生成入口，但适配器、返回类型与配置不同。先学普通入口，再观察初始方案、LP、定价、加列和最终整数求解。
:::

HTTP 响应结构、租户隔离和业务配置由应用负责，框架提供通用分切模型。LP、MILP 和列生成的含义见[术语说明](../#terminology)。

候选较少、便于检查全部方案时先用 `Csp1dMilp`；宽度组合或订单增多时再用 `Csp1dColumnGeneration`，显式限制初始方案数、每轮新增方案数与迭代次数。不存在通用的订单数分界，需按候选增长和后端资源评估；[第二课](./business-scenario#entry-budget)给出同一输入的切换代码。

## 能力边界

- 需求的产品、数量和单位必须同时明确；不能把不同单位的需求合成一个裸数。
- 设备有数据不代表每一种产能约束都自动存在，必须核对方案资源消耗与配置。
- 初始方案无法满足需求时，可能需要先补充可行候选；当前候选集合无解不等于完整业务问题无解。
- 启发式或有界定价结束不自动证明整数最优。

## 学习路线

1. 完成[环境准备](../setup)。
2. 跟随[第一次卷材分切](./first-slitting)，检查方案使用次数如何换算为产量。
3. 增加超产上界、欠产惩罚、余料和长度配置，再考虑自定义建模步骤。
4. 阅读[复杂示例 3](/zh-cn/examples/framework-example3)及其上下文模型，理解组合与列生成。
