# 刀缝、工艺与卷材：能放下不等于能加工

完成[第一次板材套裁](./first-cutting)后，按“刀缝 → 切分树 → 卷材”逐步改变问题。每次重新生成图案，而不是只改最终报表里的工艺名称。

## 1. 先用一刀理解刀缝

把 `10 × 6 m` 原料在 x=4 m 竖切，刀缝为 0.5 m。正确结果为：左块宽 4 m，右块从 x=4.5 m 开始、宽 5.5 m；宽度守恒为 `4 + 0.5 + 5.5 = 10`。不能让左右两块继续合计 10 m，还声称扣掉了刀缝。

沿用第一课的产品与需求，仅改变对应工艺或刀缝后重新调用；工艺与几何结果必须一起复核。

练习：两种产品分别为 `4 × 6 m`、`6 × 6 m`，各一件，禁止旋转。零刀缝时一张 10×6 板刚好切出；正刀缝时原排布不可行。重新生成并检查程序是否改用其他供料/更多板材或正确报告无可交付方案。

## 2. 再把 Freeform 改为断头台

| 必须保留的信息 | 为什么 |
| --- | --- |
| 区域位置与宽高 | 每个子区域必须来自实际父区域 |
| 刀向、刀位和刀缝 | 决定子区域边界与被移除的材料 |
| 工艺级数 | 两级和三级不是任意深度切割的别名 |
| 产品叶子与坐标 | 几何放置要与树的叶区相符 |

不要只检查“树非空”：每个产品必须对应叶区，每次切分必须守恒，树的最大级数不得超过工艺限制。沿用第一课的真实后端配置即可，不需要测试 profile。

换工艺后应同时更新生成配置、图案校验和验收。没有两级候选不证明任意工艺都不可加工；应报告当前工艺与候选搜索范围。

在第一课 `runExample` 中，用下面的 `changed` 替换原 `problem` 传给 `solve`。这是已有变量上的修改片段，不是另一个独立程序：

```kotlin
val changed = problem.copy(
    process = CuttingProcess2.GuillotineTwoStage,
    kerf = FltX(0.5) * Meter
)
```

## 3. 卷材按消耗长度计量

卷材有固定幅宽，但每个切割方案还需实际段长。若一个图案消耗 4 m、执行 3 次，则总消耗为 12 m，不是“使用 1 个图案”，也不等于“只消耗 3 m”。

## 4. 明确目标和损耗口径

定尺模式先关注张数；卷材模式先关注消耗长度。若混合原料、不同幅宽或费用，必须显式选择统一目标，不能把“张”和“米”直接相加。

损耗至少区分产品净面积、消耗材料面积、刀缝损失和剩余区域。可回用料需要自己的最小宽高/工艺标准，不是所有空白区域都能回库；也不要在没有字段依据时声称框架已给出上述每项独立分解。

## 5. 新应用的验收清单

1. 产品贡献乘使用次数满足订单，且没有超出配置允许的超产。
2. 原料使用不超库存，卷材段长乘使用次数与总长一致。
3. 实际坐标无越界、无内部重叠，刀缝在生成和验证中口径一致。
4. 断头台树满足级数、刀向、子区域和叶子规则。
5. 结果保留实际默认启发式/原生后端及终止语义；没有追加图案不自动等于真实 LP 定价收敛。
